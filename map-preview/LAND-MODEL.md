# 地図版：土地タイプ別モデル R5

実装元：`codex/map-linked-preview`、移行前コミット `cb68e07db19f513f81101615ef8ac773d31f9c22`。
通常版の入口と人物生成エンジンは維持。地図版の抽選母集団と標準表示を変更。

## 移行前の依存関係（Phase 1）

- `build.mjs` が国勢調査、施設、男女別学、街属性、緑地・水域と独自100m格子をまとめていた。
- `mesh-model.js` の `components()` がセル中心で確定した土地種別・住宅密度・街タグを人数と人物役割へ変換。
- `app.js` は区人口でメッシュ住宅密度を正規化し、メッシュ人口に `MapModel.components()` の施設人口を加算。
- `MapModel` の施設円と `SchoolPolicy`、`SpecialFacilities` が学校の男女区分、駅・放送局などを担当。
- `adapter.js` が役割を既存の年齢・性別・職業・名前・趣味・状況生成へ接続。
- 旧方式は保存し、旧100m格子は比較表示のみ。新モデルはセルの分類・属性・住宅密度を参照しない。

## 新しい依存関係

1. `profile-cache.js`：範囲を包含する施設データを検索。7日保存、同時問い合わせ一本化、失敗後60秒抑制、24秒で打切り。保存不可でもメモリで動作。
2. `osm-profile.js`：OpenStreetMapの点、閉じたway、multipolygonを変換。分割・逆向き外周と穴を扱う。不完全な応答は保存しない。
3. `spatial.js`：境界・面積・円内標本点・索引。索引格子には土地性や人物属性を固定しない。
4. `land-profile.js`：水域、保護対象の敷地、施設ポリゴン、概略緑地、施設点の仮定敷地、用途地域と近傍施設、情報不足時補完の順に判定。半径内の面積を合成。
5. `land-estimator.js`：`estimatePopulation()`、`estimateDemographics()`、`estimateOccupations()` を分離。人数に比例して役割を合成し、既存人物生成へ渡す。
6. `app.js`：現在の範囲と日時のみを反映。遅れて返った別地点の取得結果は画面へ適用しない。面積比と人物抽選比を区別。

## 地理的根拠と実装範囲

| 入力 | 実装・利用 | 制限 |
|---|---|---|
| 国土数値情報 A29-2019 東京都用途地域 | 東京23区171分類区域に集約、境界を簡略化して同梱 | 用途の指定であって建物実用途ではない。図面由来の位置誤差あり |
| 学校 P29-2021／福祉 P14-2023／医療 P04-2020 | 既存施設を再利用。OpenStreetMapの同施設敷地と照合し二重加算を抑止 | 規模は既定定員。最新の閉校・移転等を保証しない |
| 女子校・男子校 | 既存 `school-sex.json` をビルドで学校に適用。生徒だけを補正 | 職員・保護者・来訪者は別枠。未確認と共学を区別 |
| OpenStreetMap／Overpass | 範囲内施設、敷地、建物用途、対応書式の営業時間。端末キャッシュあり | この実行環境では実サービスが406／タイムアウト。実データ取得成功は未検証 |
| 既存公園・工業・水域 | メッシュ化前の境界を参照 | 手作業概略ポリゴンと公的水域が混在。由来を保持 |
| 街の個性 | 既存 `areas.json` 全体を使用。秋葉原、新大久保、神保町の不足タグを追加 | 文化的属性はモデル仮定。居住者の国籍を決めるデータではない |
| 人口統計 | 区人口・年齢性別分布を住宅と情報不足時に限定。用途地域の住宅面積で密度補完 | **250m人口統計は未収録**。区内の住宅人口差は建物用途と近傍施設による推定 |
| 駅 | 既存位置・推定滞在定員と朝夕補正。任意の `dailyPassengers` と `dwellMinutes` を利用可能 | 実乗降客数未収録。駅の推定定員を実測値と扱わない |
| 事業所・従業者 | オフィス・工場・物流の土地別密度モデル | 経済センサスの従業者分布は未収録 |

対象は現行同様、東京23区。16大分類に対応。主分類・副分類・面積比を保持する。
緑地は住宅統計を使わず、学校は生徒＋職員＋来訪者。住宅昼間の在宅者を別職場で勤務中として描写しない。
小規模施設の円やポリゴンの部分交差は数値積分の近似。15m相当の標本密度、最少384点・最大10,000点で、細い境界・極小施設には誤差がある。
原則として一つの地点を一つの地表用途へ割り当てるため、同じ建物の上下階で住宅と店舗が重なる垂直混在、橋上・地下階は未対応。

## 外部データの再生成

```sh
# pyshp, shapely が必要。原典ZIPはリポジトリへ含めない。
python map-preview/import-zoning.py /path/to/A29-19_13_GML.zip
# Overpassが利用できる環境で6地点のオフライン種データを更新（逐次取得）
node map-preview/prefetch-osm.cjs
npm run verify
npm run test:land
node map-preview/land-comparison.cjs
```

原典： https://nlftp.mlit.go.jp/ksj/gml/data/A29/A29-19/A29-19_13_GML.zip
仕様・利用条件： https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-A29-v2_1.html
OpenStreetMap： https://www.openstreetmap.org/copyright （Open Database License 1.0）
Overpassの公開サーバーには稼働保証がない。広域・多数利用に拡張する場合は事前抽出を優先する。

## 検証

- `land-estimator.test.cjs`：6地点の分類差、森への住宅漏出防止、混合半径、学校性別、平日休日深夜、敷地と施設点の重複、既存人物生成への接続。
- `profile-cache.test.cjs`：ポリゴン内部・穴・分割境界、営業時間の翌日持越し、キャッシュ包含範囲・期限・永続化・同時要求、通信と保存の失敗。
- `land-model-validation.json`：6地点×2半径×3時間条件、旧方式との理論比較。**観測人口の検証ではない**。
- DOM統合：初期表示、地点・半径・日時変更、キャッシュ再利用、旧表示切替、学校検索、人物生成を模擬通信で確認。
- ブラウザ実描画：Chromiumダウンロードが破損応答となり、この環境では未確認。
- 既存green/landテスト2件は移行前にも件数条件で失敗。対象が23区へ縮小された事情に合わせ、区域内の各施設で生成できることを検証する形へ修正。
